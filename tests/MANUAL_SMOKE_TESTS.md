# KeyTrain manual smoke tests

Use the current known-good iOS/firmware pair and a test device. These nine scenarios cover behavior the host suite cannot establish. They have **not been executed by this testing pass**. Keep firmware/app versions and the diagnostic export for any failure. Do not reset a personal device or clear saved bindings to run this suite; use a spare already intended for setup testing when needed.

| ID / Scenario | Setup | Action | Expected observable behavior | If it fails, inspect |
|---|---|---|---|---|
| M1 Cold boot/connect/refresh | Bound device, selected city, working network, required Bluetooth/location permissions. For a new spare, complete ordinary onboarding first. | Cold boot device and open/connect the app. | Correct permanent device identity is selected; a fresh complete board replaces initial/retained state. Onboarding completes only after settings confirmation. No partial board is displayed. | BOOT_START/BOOT_READY, BLE_CONNECTED, identity verification, DATA_REQUEST_SENT, FETCH_SUCCESS, DATA_APPLIED, DATA_APPLIED_ACK_RECEIVED, DISPLAY_UPDATED. |
| M2 Repeated refresh | A working connection and a displayed board. | Exercise ordinary wake/refresh several times, including an opportunity after 60 seconds. Observe another request after a failed attempt if possible. | Freshness policy suppresses unnecessary requests; a real new demand is serviced. Retry of one transaction uses the same payload bytes; a new transaction may fetch new data. A failed attempt retains the last valid board. | Request IDs, DATA_REQUEST_COALESCED, response byte counts/CRC where logged, REQUEST/RESPONSE stages, age indicator. If exact byte reuse cannot be observed, mark that subcheck unverified. |
| M3 Disconnect/reconnect and device switch | Bound device A. Optional saved device B with visibly different colors. | Disconnect, reconnect; if B is available, switch to B, then back to A. Attempt switching while a normal operation is busy. | Connection targets the selected identity; old-session responses cannot apply to the newly selected device. Busy-operation behavior remains consistent with release 1. Verify both devices' actual colors rather than trusting the cached confirmation label. | Identity checks, session/generation logs, cancelled writes, theme ACK tokens. Known audit concern: cross-device deviceTheme deduplication; report any missed live edit instead of accepting it as desired behavior. |
| M4 Device reboot with active phone | Keep app and phone Bluetooth active. | Reboot only the device, then allow reconnection. | New boot/request identity is recognized; arrivals resume without restarting the phone app. An old transaction's ACK cannot confirm the new boot's request. | Boot ID, connection/session transitions, applied ACK unexpected/rejected/received events. |
| M5 Background and return | Always location permission, Bluetooth permission and normal background settings; known-good foreground refresh first. | Lock/background the phone, wake/request from the device, then return to the app. | Where iOS grants execution, a background response completes. Expiry/failure is visible and recoverable when foregrounded; no falsely confirmed update or permanent busy state. Force-quit behavior is not a guaranteed background-delivery contract. | Foreground/background request flag, background expiration/deadline logs, LOCATION/API/FETCH failure, response/ACK stages. |
| M6 Interrupted operation and recovery | Working connection; choose a normal transit send or palette save. | Move out of range or disable phone Bluetooth during the operation. Restore it, reconnect and repeat the operation. | Old operation cannot acknowledge success for a new session; the UI/transport can send again. Keep the previous board/settings on incomplete input. If busy persists beyond the documented operation deadline after reconnection, retain diagnostics. | Write completion/failure, disconnect, generation reset, refresh deadline, theme/mode timeout. Missing CoreBluetooth callbacks and cancellation are not covered by host tests. |
| M7 Persisted settings and binding | Bound test device; record current palette/mode and device ID. | Save a visibly different palette and compact/standard mode; wait for confirmed saved state. Restart app and device, then restore original settings. | Confirmed settings survive restart; device identity/binding survives. Standard shows three and compact six arrivals. A failed/unacknowledged save is not labelled confirmed. | Palette/mode command and matching persistence ACK, NVS errors, selected versus confirmed UI state. Interrupted first claim requires a spare and is an additional setup subcheck, not a personal-device reset. |
| M8 Input/display during communication | Board with two stations, multiple platforms and enough arrivals for paging. | While refreshing, use single/double presses and a long hold; allow automatic pages to cycle; wake after display standby. | Wake-only press stays wake-only. Navigation stays responsive and station/direction identity is stable; first page dwells about 8s and later pages about 6s. No partial redraw/flicker, clipped ETA or stale color after transitions. | Input/navigation, render generation, DISPLAY_UPDATE_START/COMPLETE, watchdog logs. Check compound direction labels and 1/2/3/4-digit ETAs visually. Pixel bounds and TFT stalls remain manual. |
| M9 Diagnostic export/cancel/retry | Some retained phone/device events; enough storage for export. | Collect and open raw/normal/verbose exports. Repeat and cancel/interupt before completion; reconnect and retry. | Successful export is validated and saved before receipt ACK permits purge. Cancelled/incomplete export does not intentionally purge. A retried matching ACK is idempotent; later events survive. | DIAG export ID, CRC/offset errors, save/readback success before ACK, device confirmation and sequence cutoff. Real disk/NVS failure and exact purge cutoff need an instrumented integration session; ordinary smoke cannot prove power-loss atomicity. |

Do not use a passing smoke run as permission to restructure BLE ownership, render-task synchronization or diagnostic purge logic. Record any unexercised branch as unverified. Provisioning security, fallback policy and radio/battery tradeoffs require design decisions, not smoke-test expectation changes.
